# Independent Coela producer acceptance

This owner consumes the real native Coela definition distributed as
[semantic source 0.1.0](https://github.com/coela-oss/engineering/releases/tag/semantic/v0.1.0).
`conformance/source/fixtures/coela-evidence/provenance.json` admits its exact source,
archive and file digests. Fixture `.sem` and descriptor bytes are preserved without
editing; update them from a reviewed upstream release rather than rewriting the
producer's vocabulary here. Original CC-BY-4.0/MIT attribution and licenses remain.

The standard verification command already executes this independent conformance
crate. Two additional cases use this owner's native compiler/standard definitions,
explicit revision-checked adoption, filesystem checkpoint/reopen and bilingual
meaning compilation. Unknown surfaces and stale semantic revisions do not resolve;
undeclared dependencies and conflicting producer definitions cannot adopt.

The selected term means a reported implementation-evidence category. Compiling that
meaning is different from proving its factual relation. With no asserted evidence,
the runtime must preserve NeedsResolution/MissingContext, zero runtime claims and
no capability bindings. Reopening storage does not adopt new meaning or grant an
operation. A model, live service, secret or Hatter initial-definition choice is not
part of this fixture.

Run `cargo test --locked --manifest-path conformance/source/Cargo.toml` on an approved
runner. Source tests do not certify publisher trust, application judgment, signed
HAT/runtime installation or real inference-owner cancellation/replay. Those broader
requirements remain in issue #1; the existing actual-owner ignored inference case
is not changed or reported successful. Library/package versions stay 0.10.0 and no
existing immutable registry artifact is replaced by this consumer-only acceptance.
